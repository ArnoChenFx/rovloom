# 管理页

管理页内置在 Gateway 中，用于查看已配对设备及其 Luvus/Herdr provider 的状态，并执行少量管理操作。Connector 不提供管理页。管理页不管理 LLM 的 API key，也不提供终端、任意 shell、结果浏览或多租户。系统语义见 [DESIGN](DESIGN.md)。

## 访问

- 默认地址是 `http://127.0.0.1:9445/`。端口和开关由 Gateway 配置的 `management.port` 与 `management.enabled` 控制，见 [配置参考](CONFIGURATION-zh.md)。
- 默认监听地址为 `127.0.0.1`，请求的 Host 必须是 `127.0.0.1:<port>`。从其他机器访问时，使用 SSH 端口转发，并让本地端口与 `management.port` 相同。
- 把 `management.hostname` 设为 `"0.0.0.0"` 后，管理页即接受局域网 Host 的明文 HTTP 访问（见 [配置参考](CONFIGURATION-zh.md#每个用户参数)）。Cookie 仍为 `HttpOnly`/`SameSite=Strict`，跨站请求仍被拒绝，但没有传输加密：请勿在不可信网络中开放此选项，必要时用 TLS 反向代理收口。保持 `127.0.0.1` 时只接受回环寻址，局域网访问返回 403，行为与原来完全一致。
- 管理页使用 HTTP Basic 登录。用户名是管理员 ID，默认 `admin`。
- 首次配对经 Gateway 终端完成时，会自动创建管理员 `admin` 并只显示一次密码。也可以在任何配对之前运行 `rovloom admin create` 手动创建，然后从管理页完成首台设备的在线配对（见下文「在线配对」与 [配置参考](CONFIGURATION-zh.md#管理页管理员)）。之后用 `rovloom admin create|list|revoke` 管理，创建与修改都不需要重启。
- Gateway 只保存密码的 SHA-256 摘要。创建、重新签发和撤销都不需要重启。管理员被撤销或密码被替换后，对应浏览器会话在下一次请求时失效。
- **登录状态会保持。** 首次用 Basic 登录后，浏览器收到 `Path=/`、`HttpOnly`、`SameSite=Strict` 的会话 cookie。此后刷新页面、Gateway 因配对重载、以及 Gateway 进程重启都不再要求重输密码：cookie 与租期的绑定以 SHA-256 摘要形式保存在 `<state.dir>/managed/management-sessions.json`，重启后重新加载并逐次复验原管理员记录。撤销管理员、重新签发密码或租期到期仍会立即让旧 cookie 失效。该文件不含 cookie 或 CSRF 原值；文件损坏或超限时按「没有可恢复会话」处理，不阻塞启动，且损坏文件会在下一次成功登录后被覆盖，不会永久阻止后续持久化。
- 同一租期可并存多条绑定：重启后新打开的页面会追加一条新 cookie，而其他浏览器和此前已打开的标签页持有的旧 cookie 与 CSRF 继续有效（每个租期最多 8 条，超出后淘汰最旧的一条）。撤销管理员或租期到期时，该租期的全部绑定一起失效。
- 从 `Path=/admin/v1` 升级的浏览器会在下一次页面交付时收到一条 `Max-Age=0` 的同名 cookie，显式清除旧路径的残留值；否则旧 cookie 会与新 cookie 同时出现在 API 请求上而被拒绝认证。
- 没有任何管理员时，页面只交付没有数据的空壳。存在管理员后，没有有效凭据的请求一律返回 401。
- 管理员可以查看和管理 Gateway 已知的全部设备和 provider，包括之后才配对的。
- 管理员不能调用 MCP。MCP Bearer、设备凭据和一次性配对码也不能登录管理页，三者互不替代。
- 不要把管理密码、Bearer 或配对码放进 URL 或日志。

## 设备与 provider 状态

设备列表显示设备 ID、名称、连接与认证状态、最近心跳和各层状态的观测年龄。详情分区显示：

- 连接与认证状态；
- 持久登记状态（待配对、离线、在线、已撤销）；
- 已配置的 provider 行，包含 provider ID、类型（`luvus` 或 `herdr`）、绑定 revision、启停状态和运行状态；
- Gateway 的监听、认证状态和各组件状态。

状态的含义：

| 状态 | 含义 |
|---|---|
| 待配对 | 设备已登记，还没有有效凭据。不显示为在线 |
| 在线、已认证 | Gateway 对实际 WebSocket 的观测。没有证据时显示为未核实，不从持久化的 `online` 推断 |
| 最近心跳 | Gateway 收到合法心跳的时刻 |
| provider ready | 设备在线且已认证，并且该 provider 的运行观测是最新的。传输层的派发就绪不等于原生 runtime 可达 |
| 存储降级 | Gateway 全局只读，禁止管理写入 |

每层状态按各自的观测时间计算新鲜度。连接、认证、provider 登记和运行观测各自超过 15 秒就视为过期，只作历史显示，不显示绿色在线或 ready。新的整体读取不会刷新旧的子观测。

页面没有 Gateway 的实际监听范围、设备 OS 版本和管理员会话截止时间，缺失处如实显示为未核实。设备名、标签、ID、方法名和协议引用保持原文。页面不显示设备凭据或原生输出；管理员可在 MCP 管理区查看和复制 MCP Token。

## 刷新

- 页面可见时每 5 秒读取一次，隐藏时暂停，回到前台立即刷新。单次读取超时 5 秒。
- 距上次成功读取超过 15 秒，或设备 epoch 发生变化，就标记为过期，并禁用基于该快照的写入，直到刷新。
- 断网时保留带过期标记的只读视图，不伪装成实时数据。
- 读取返回 401 时，清空内存中的数据并停止轮询。404 表示资源不存在或无法查看。409 需要刷新后重新确认。

## 管理操作

设备详情提供以下操作：

| 操作 | 效果 |
|---|---|
| 重命名 | 修改设备名称，不改标签 |
| 断开 | 关闭指定 epoch 的连接，保留持久授权。Connector 可以再次连接。不会停止原生工作 |
| 撤销 | 持久撤销设备凭据，关闭连接，拒绝新的认证和派发。已送出的动作可能继续，结果为 unknown。撤销后不能重新配对，需要作为新设备重新首次配对 |
| 删除设备 | 删除设备、provider 运行配置、关联配对记录和调用内容，断开连接；再次连接需要重新配对 |
| 禁用 provider | 只禁用选定的 provider 实例，绑定 revision 加一，阻断该实例的派发、读取和补证，并关闭其流。不影响设备凭据和同设备的其他 provider |

首次配对全程可在页面完成：`rovloom admin create` 创建管理员并登录页面后，在「配对设备」生成一机一码，把显示的加入命令复制到 Connector 机器执行即可（终端用 `rovloom gateway --issue-code` 也能打印一条）。没有申请、批准或核对码。页面不提供 provider 启用入口。

改名、断开、撤销、禁用 provider 和配对批准沿用两步确认；创建 Token 直接提交，删除 Token、设备或配对记录只需一次删除确认。原有两步确认流程：

1. 页面先获取后台摘要，展示目标、精确的连接 epoch 或 revision、原因和影响，由管理员确认。
2. 确认后才提交。确认记录由后台保存，绑定当前管理会话、操作摘要、目标和 revision，只能使用一次，2 分钟后过期。过期、操作摘要变化或 revision 变化都需要重新确认。

提交后的行为：

- 重复点击不会产生第二次提交。
- 结果未确认时，页面显示"结果未确认"，保留原关联，只查询原操作的回执，不自动重新提交。
- 回执只表示持久提交。物理通道是否已关闭、原生工作是否继续，页面如实标注。
- 会话或权限失效后，页面清空详情和确认内容并停止自动轮询；「刷新」按钮仍可用，cookie 会话恢复后点一次即可继续，不必重新加载整个页面。
- 存储降级时，所有写按钮禁用。后端也会独立拒绝对应请求。持久撤销可能尚未生效。

## MCP Token

打开「连接 MCP」，输入名称、选择有效期后直接创建。新 Token 默认 365 天，可选 7、30、90 天；
可以访问当前及之后配对的设备。列表支持显示/隐藏原文、复制和删除，刷新页面或重启 Gateway 后仍然可查看。
删除后，已有 MCP 会话在下一次请求时失效，不需要重启。

为支持后续查看，新 Token 的原文与认证摘要一起保存在 Gateway 的私有 `managed/mcp-callers.json`。
CLI 新创建或轮换的 Token 同样可查看。旧的纯摘要记录不能还原，若已有 `mcp-client` 原文副本则使用该副本；
否则可在列表中重新签发，旧 Token 立即失效。管理员密码仍只存摘要，不受此功能影响。

「配对设备」面板列出全部配对码：未使用的码显示完整加入命令（可复制、可作废），
已用/作废/失败的码保留状态与时间供对账。需要移除设备时，到设备详情执行「删除设备」。

上述管理请求通过 `/admin/v1/resources/` 下的固定 POST 路由，复用现有管理员 Cookie 和 CSRF；
仅完整 Gateway 管理员可使用，不向 MCP 调用方开放 Token 管理或删除权限。

## 配对码

「配对设备」页面管理一机一码，Gateway 全程不停机：

1. 点击「生成配对码」（可填写备注名），页面立即显示完整加入命令并附复制按钮，例如
   `rovloom connector --join ws://192.168.1.10:9443#机器.码ID.秘密`。加入命令的地址取自
   当前浏览器访问管理页所用的主机名，跨机器部署时即为目标机器可达的地址。
2. 未使用的码保留明文，刷新或重启 Gateway 后仍可重新显示与复制；已用、作废或失败的码
   明文立即抹掉，只保留状态与时间。
3. 一码一设备：第一次成功兑换即消费该码；第二个设备使用同一码会得到 `pairing_code_used`
   错误，重新生成即可。作废未使用的码会一并删除其占位设备行。
4. 配对完成后设备自动进入设备列表，几秒内转为就绪；无需任何页面操作。

## 语言与主题

- 语言默认按浏览器语言匹配简体中文或 English，其他语言使用 English。点击右上角语言图标即可在中英文之间切换，不展开菜单。
- 主题默认跟随系统，点击右上角太阳/月亮图标即可在浅色与深色之间切换，不展开菜单。手动选择会记住，刷新后保留。
- 选择保存在浏览器 `localStorage` 的 `rovloom.webui.language` 和 `rovloom.webui.theme`。不保存身份、token、设备数据或快照。存储不可用时，选择在当前页面内仍然有效。

## HTTP 接口

页面通过同源接口访问 Gateway。接口版本 `/admin/v1` 与 Wire 和 MCP 的版本无关。

读取接口，均为 GET：

| 路径 | 内容 |
|---|---|
| `/admin/v1/status` | 服务时间、模式、管理策略和刷新建议 |
| `/admin/v1/devices` | 设备摘要，支持 `cursor`、`limit`（默认 50，最大 200）和 `states` 筛选 |
| `/admin/v1/devices/{machine_id}` | 设备详情 |
| `/admin/v1/devices/{machine_id}/providers` | provider 列表，分页 |
| `/admin/v1/devices/{machine_id}/providers/{provider_id}` | 单个 provider |
| `/admin/v1/devices/{machine_id}/permissions` | 当前管理员对该设备的权限提示，可用 `provider_id` 指定 provider |

写入接口为 `POST /admin/v1/actions/<action>`，其中 `<action>` 包括 `confirmations_create`、`confirmations_confirm`、`devices_rename`、`devices_disconnect`、`devices_revoke`、`providers_disable`，以及查询回执的 `operations_get`。每个写请求带请求 ID、预期 revision 和确认 ID 等字段，后端按管理员和目标去重。

安全约束：

- 每个请求都重新认证，并检查具体的管理权限。静态页面壳不含数据。
- 浏览器会话使用 `HttpOnly`、`SameSite=Strict` 的 cookie 和 CSRF 令牌。请求的 Origin 必须同源，跨站请求被拒绝。
- 响应带 `no-store`、固定的 CSP 和 `nosniff`，不提供 source map，不设置 CORS。
- URL 最长 32 KiB，请求头最多 48 个、共 16 KiB。单次输出最多 512 KiB，每页最多 200 项。
- 同时进行的读取最多 16 个，读取超时 5 秒。全局准入桶允许突发 32 次，每秒补充 8 次，未登录的请求同样计费，耗尽时返回 429 和 `Retry-After`。
- 后端错误映射为固定的 HTTP 分类：未认证 401、无权限 403、不存在 404、参数无效 400、版本冲突 409、超时 504，其余不可用 503。响应不包含异常原文。

## 备份恢复后的页面

从备份恢复的 Gateway 正常启动，所有设备回到待配对，所有 provider 默认禁用并需要重新确认。恢复前的在线状态和权限数据不会出现在新状态里。详见 [存储与数据保留](STORAGE.md#备份与恢复)。
