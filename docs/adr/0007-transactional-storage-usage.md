# ADR 0007：事务用量计数与过期索引

状态：已采纳并实现。本文记录 schema v9 引入时的决策；当前 schema 和 v9 → v10 迁移边界见 [存储](../STORAGE.md)。

## 依据

32 台设备、64 个 provider 的磁盘聚合回放确认，每次写事务中的内容和预约 SUM 随调用历史线性增长。1024 是单个 Connector claim ledger 的保护期内条数上限，不能限制 Gateway 的多设备历史或登记后未派发的调用。量测方法、原始数据和边界见[量测报告](../performance/249-aggregate-storage.md)。

## 决策

Gateway schema 升为 9。在同一 SQLite 库增加唯一 `storage_usage` 行，记录请求与响应的 UTF-8 字节、结果句柄字节、未释放的收尾预约。calls/results 的 INSERT、相关字段 UPDATE、DELETE 由 SQLite 触发器更新计数，包括外键级联删除。预算检查读取这三个计数，仍逐次核对实际数据目录、journal、快照目录、物理页与安全预留；不缓存文件占用。

计数与原写入共用同一事务：预算拒绝、业务拒绝、before_commit 故障、SQLite 回滚都不能提交一半。结果丢弃、TTL 清理、unknown 预约保留、恢复和脱敏快照均走同一触发器。快照从零计数开始，只随真正复制的行累积，不复制原库计数或有效结果。

启动（恢复写入前）和离线只读检查核对六个计数触发器的定义并重新 SUM，核对计数与业务表一致，发现不一致以 `database_integrity_failed` 拒绝，不自动修正。完整扫描因此移出热路径，而不是取消一致性验证。当时保留 schema 版本拒绝规则，未提供迁移器；后续 v9 → v10 迁移不改变本 ADR 的事务计数设计。

为活调用 deadline、尚有内容的 content_expires、dedup_expires 添加索引。已清空的历史不再每秒重复 UPDATE；失效通知排队后先删除完全到期的调用，避免同一事务中先清空又删除，零差异更新也不触发计数写入；结果清理从结果行按主键核对其调用，不先枚举全量调用历史。调用终态、TTL 边界、提交后失效通知和不自动重派的语义不变。

## 限制与验证

索引和触发器增加磁盘与写放大，实测登记总耗时包含这些成本。到期突发仍按原规则在一个事务内清理，不承诺硬实时预算；批量过期耗时单独报告。没有用扩大默认配额或削减保留期限换取结果。

回归使用独立只读连接的实际 SUM 为 oracle，覆盖多字节文本、派发预约、响应提交、结果句柄、丢弃、TTL 删除、before_commit 回滚、快照、正常重启及损坏计数。已有配额、降级、备份失败和恢复测试继续适用。
